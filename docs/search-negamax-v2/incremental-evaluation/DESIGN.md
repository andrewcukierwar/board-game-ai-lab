# Phase 3B.1 declaration (before timing)

Baseline: immutable Git object 93ee943d8744651064dcf9a3a79108d6ca73af53.
Only evaluation storage and play/undo updates may change. The 69 windows,
weights (0,1,3,9,81), mover perspective, search flow, terminal precedence,
depth-sensitive scores, root order, full-window root scores and TT semantics
must remain identical. Every result and all search counters must agree.

Compare compact X+5*O counts with direct play deltas and saved-score undo,
compact counts with inverse deltas on undo, and separate X/O count arrays.
Select the fastest eligible variant by geometric mean across non-tail rows;
report all variants, including regressions. This is a finite engineering
comparison, not a statistical population claim.

Acceptance, fixed before measurements:
- Independent array geometry/evaluation, thousands of legal branching play/undo
  transitions, complete rollback and exception restoration must pass.
- Every timed, counted and memory run must reproduce the baseline move, ordered
  entire root-score vector, nodes, entries, hits, cutoffs and heuristic leaf count.
- At depths 6/8/10, broad trees (baseline >=2,000 nodes and >=35% heuristic
  leaves, classified by deterministic counters) require >=1.15x geometric-mean
  speedup and improvement on >=80% of these conditions.
- Across all non-tail positions/depths: >=1.05x geometric-mean speedup and >=10%
  reduction in the sum of median latencies. Equal condition weighting for the
  geometric mean; the sum additionally describes this fixed search workload.
- Every non-tail condition must have slowdown <=50% OR added latency <=0.25 ms.
  This permits small absolute costs on terminal-heavy/tiny trees; report both
  relative and absolute regressions, without hiding them in aggregates.
- Retained TT objects must agree in size. Per-condition traced peak growth must
  be <=5% OR <=32 KiB. Report persistent evaluator lookup storage separately.
- Complete backend suite must pass with dotenv disabled and providers forbidden.

Performance fixtures: every Phase 3A base and supplement manifest history;
eight additional legal nonterminal histories, seed 20261009, two each at
8/12/16/20 plies, generated by uniform legal moves with terminal rejection only.
No position selection uses measured speedup. [1,4,6,0,6] is a post hoc cost-tail
diagnostic and is excluded from all acceptance aggregates.

Depths 4/6/8/10, one discarded warm-up per condition/variant, seven timed runs
with rotating before/after/ablation order. Each run measures complete ordinary
choose_move wall and process CPU time with a fresh production TT and no wrappers.
Separate untimed leaf-count instrumentation and retained-TT tracemalloc runs
assert the same results/counters. Memory runs are repeated twice. Isolated
heuristic calls and play/heuristic/undo cycles are separate microbenchmarks:
these cannot stand in for choose_move speedups. Source hashes and runtime/host
metadata are frozen in manifest.json before run. New evidence never overwrites
an existing output or earlier phase artifacts. No services, providers, models,
public presets or production environments are used.

Measurement calibration before the final repeat: construct and discard 64
SearchTable instances in each module before any measured searches. CPython
shared-key instance dictionaries shrink across early constructors; equal
constructor warm-up removes a 104/16-byte bookkeeping artifact on the first
two rows. The complete uncalibrated run is preserved in pre-calibration/,
including its original harness. No acceptance threshold or position changes.
